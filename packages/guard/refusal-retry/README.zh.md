# @deepseek-ai/dsh-refusal-retry

轮次级守卫。一轮本该结束时，如果最后的回答以拒绝开头，守卫改用下一档臂在**同一轮内**继续，而不是让拒绝成为答案。

它读取会话里最后一条 `assistant/message`，做分类；对没有发起工具调用的拒绝，追加 `refusal/retry` 事件，并通过 `agent.steer` 送入带标签的续写消息。整轮保持同一个身份：不新增轮次边界，也不会在对话里多出一条用户提问。

## 配置

```yaml
- id: refusal-retry
  name: '@deepseek-ai/dsh-refusal-retry'
  config:
    arms: [1]
    maxPerTurn: 2
    maxPerSession: 6
```

| 字段 | 默认 | 含义 |
|---|---|---|
| `arms` | `[1]` | 依次升级的臂。`1` 重申交付、`2` 放进虚构框架、`3` 从被拒回答中断处接着写完。空列表即关闭守卫。 |
| `maxPerTurn` | `2` | 单轮允许的续写次数。 |
| `maxPerSession` | `6` | 整个会话允许的续写次数。 |

## 分类

| 结论 | 条件 | 守卫动作 |
|---|---|---|
| `delivered` | 无拒绝开头，或该回答发起过工具调用 | 不动 |
| `refused` | 开头是拒绝，且回答短于 500 字符 | 续写本轮 |
| `partial_refused` | 开头是拒绝，但后文仍有相邻内容 | 不续写（只记录） |
| `empty_after_retry` | 回答为空 | 不续写（只记录） |

拒绝开头只在回答的前 220 字符里匹配，中英两种句式都覆盖。思维块不参与判断，只算可见文本。

## 模型体验

每次续写都是同一轮里的一个额外请求，复用该轮已缓存的前缀；增量成本是续写消息加它产生的回答。发起过工具调用的回答不触发守卫，所以工具型工作零成本。`refusal/retry` 记录轮次、臂、结论与被拒回答长度，额外开销可按轮归因。

## 已知限制与后续工作

- 分类是对回答开头的模式匹配。用不常见句式写的拒绝、或者在长铺垫之后才出现的拒绝，不会被识别，也不会被续写。
- 既拒绝又发起工具调用的回答按已交付处理；守卫不判断工具调用的意图。
- 服务端层面的拒绝（`stop_reason: refusal`）不续写，因为它没有可分类的回答。
- `partial_refused` 与 `empty_after_retry` 只记录不续写，与社区版 1.7.20 的标签口径一致。
