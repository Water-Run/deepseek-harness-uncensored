# @deepseek-ai/dsh-target-protection

English | [中文](README.zh.md)

## Summary

This optional backend protects named production targets in HTTP and local file operations. It binds DNS to connection addresses, supports local country data, and allows structured file reads under audit rules. Production restrictions win over test exceptions. Arbitrary processes are refused when their effects cannot be confined. The default product has not enabled this integration; additional adapters and management UI remain unfinished.

## Use this package

Mount the root service with an explicit `path` to a dedicated SQLite registry. Mount `./http` instead of the ordinary HTTP fetch provider, alongside the web service. Both providers use the same ID and cannot coexist. The guarded consumer requires `targetProtection`; removing that service withdraws the consumer rather than restoring unrestricted fetches.

`busyTimeoutMs` bounds SQLite lock waits (default 1000); `checkTimeoutMs` bounds address checks (default 5000); `maxRechecks` bounds retries after concurrent configuration changes (default 3). These options do not authorize replay of a network operation.

`dnsServers` defaults to the OS resolver list; `hostsFile` defaults to the system hosts file. `dnsQueryTimeoutMs` defaults to 1500, `dnsMaxCnameDepth` to 8, `dnsMaxRecords` to 256 and `hostsMaxBytes` to 1 MiB. DNS uses these configured resolvers rather than choosing an external public resolver. Refusals and invalid replies are not evaded by asking another server.

Rules support exact hosts, domain suffixes, linear-time regular expressions and IP networks, with optional port and database identifiers. Test exceptions require an exact host or IP. Full production protection denies access. Audit protection accepts only effects guaranteed read-only by an executor; HTTP GET alone does not establish that guarantee. An exception for one IP cannot exempt another possible connection address in the same DNS answer set.

A resource can bind additional selectors in `aliases`, including network endpoints and local data paths. All selectors share its policy and ID; aliases cannot supply their own test or protection flag. Each selector states its own port and database scope without inheriting another selector's qualifiers. Database file markers also protect SQLite-style `-wal`, `-shm` and `-journal` companions. Owners must explicitly bind the relevant data paths; network addresses do not discover those files automatically.

The guarded HTTP consumer uses local resolution and literal-IP CONNECT when a configured HTTP(S) proxy is selected. Rules run before contacting the proxy; the original Host and TLS name remain intact. The proxy must support IP CONNECT and honor that destination. DNS queries use the configured local resolver, not the HTTP proxy. Failed tunnels never fall back to direct or unverified proxy requests.

Mount `./fs` instead of `fs-sandbox`, with the existing `sandboxPolicy` service. Local `path` rules identify an absolute server directory or database file and cannot include network qualifiers. Windows rules require a drive-qualified local path; remote paths are not converted into local paths. Full protection denies reads and mutations; audit permits structured reads while denying writes and edits. Production paths take precedence over overlapping test paths. Symbolic links are resolved again and full-precision file identities are compared. On Windows, native hard-link enumeration expands every mounted volume path and verifies each alias and the final link count; incomplete results or metadata changes refuse access. This recognizes links into production or owner directories while allowing unrelated test links. Other platforms still refuse unattributable hard links outside protected directories. UNC, device and alternate-stream paths need a separate adapter. Watching is currently refused.

The guarded file provider always protects the registry and its SQLite sidecars. `ownerPaths` adds configuration or credential files whose access is refused; `readOnlyPaths` adds sources that may be read but not changed. The configured hosts file and country database are also protected from changes. Owner configuration uses the rule service independently of Agent file access.

Regular-file deletion and non-overwriting rename use the same mandatory rules, including both rename endpoints and source-version validation. Enable `fileOperations` on `tool-fs` for the optional tools. Full and audit production rules deny both operations, even under full-access permissions. Policy changes are rechecked before the first effect; a committed rename finishes source cleanup while retaining the rule owner. If cleanup fails, `FS_PARTIAL_MUTATION` reports that both names may remain. Directory operations and cross-filesystem moves are unsupported.

Mount `./subprocess` instead of `subprocess-local`. It refuses ordinary processes and PTY allocation while mainland or production rules, or protected owner/data files, are present. A test hostname or full-access permission cannot bound arbitrary code. Only a composition with an in-memory registry, disabled mainland protection, no production rules and no protected local sources can delegate to the original process provider. Activating local policy cancels previously admitted processes. This provider does not provide an OS target sandbox.

Optional `./subprocess-native` replaces that admission-only provider on Windows Node 24 with the verified BaseContainer backend. It requires `targetProtection` and `credentials`, plus explicit `readonlyPaths`, `readwritePaths`, `temporaryRoot` and `network` (`disabled` or `gateway`). Grants must exist; write grants must be directories. The private root must remain outside every grant after resolving aliases. The provider supports ordinary commands and real ConPTY terminals, preserving raw/collected/control streams, cancellation and whole-range waits. Unsupported platforms are refused rather than delegated to ordinary execution.

Each command receives a private HOME and temporary directory. Ambient proxy variables are replaced by its owned gateway, or removed when networking is disabled; the Host environment is unchanged. An optional `proxy: { protocol, host, port, username?, passwordRef? }` selects the gateway's upstream. A password needs a paired username and stored POSIX-style credential reference; missing credentials fail activation and are checked again for each command. Proxy passwords never enter the command environment. Generic subprocesses have no invented conversation identity or traffic capture; Security-mode settings and capture integration remain pending.

`maxProcesses` defaults to 16 and counts executions through output settlement and cleanup. Policy scan, startup, connection, diagnostic and cleanup budgets are configurable in [`NativeTargetSubprocess.Config`](src/subprocess-native.ts). Executable lookup checks target policy before candidate metadata access and cancels on policy changes. Rule changes stop retained executions before committing. Unconfirmed cleanup prevents new work, retains the synchronous final stop and reports the cause. Private-directory deletion verifies its scope. Gateway mode still has the inbound and opaque-protocol limits described below; this opt-in is not enabled by the default product.

Native terminals start a fixed helper inside the same contained process range. User arguments and environment arrive only after helper startup, over a separate inherited control pipe; terminal bytes cannot become control replies. Input, resizing, foreground inspection and signals use bounded acknowledgements. Large input preserves UTF-16 pairs, and output uses backpressure. Allocation cancellation is detached after the handle is published. Defaults are 30 s startup, 5 s per operation and 64 pending requests; an unknown operation outcome stops the session without replay.

Closing or natural shell exit ends the entire native terminal range, including detached descendants, before releasing protection. Normal exit retains the delivered UTF-8 tail; explicit closure can discard unread output. Windows uses the shell PID as its console pseudo-group and delivers SIGINT as Ctrl-C; unsupported signals fail. Activity stays unknown or busy while prompt state cannot be verified, and becomes idle after confirmed range closure. Failed startup, paused output and detached-descendant cleanup are covered by real Windows tests. Default profile and user-interface integration remain separate work.

The registry defaults mainland protection to enabled. Mount `./country` to use the pinned DB-IP Lite dataset. Its `path` defaults to the bundled file, `maxBytes` to 32 MiB and `maxAgeDays` to 45. Missing, damaged, future or expired data cannot establish an outside destination. The `.cn` and Chinese China domain labels are separate evidence. Unresolved names or regions are refused unless an exact test exception applies. No UI reports this partial backend as complete protection.

Country data is an estimate with limited coverage and accuracy. [IP Geolocation by DB-IP](https://db-ip.com) is distributed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); see [the bundled notice](assets/NOTICE.md). A web composition using these results must display that linked attribution. Data updates currently require replacing the configured local source and reloading its provider; the product settings integration is unfinished.

Mount `./security-proxy` instead of `security-proxy-local`, with mandatory credentials and target protection. Its controlled client, HTTP relay and connection check authorize the original target before literal-IP CONNECT. Origin Host and TLS identity stay fixed; mismatched relay Host headers are refused. Redirects recheck current rules. Opaque CONNECT is refused because tunneled application targets cannot be verified; an endpoint test label does not remove this limitation. Keep the guarded ordinary HTTP provider mounted too, so disabling the independent proxy does not restore unrestricted fetches.

Mount `./ssh` instead of an ordinary SSH connection, with mandatory `credentials` and `targetProtection`, then use `fs-ssh`. It uses the [explicit direct-SSH configuration](../../ssh/ssh/README.md#direct-connection), validates the original name and DNS aliases, fixes one literal destination, and verifies the server key. Full server protection refuses before TCP; audit admits structured file reads and refuses mutations. Exact private test endpoints may perform bounded file operations without relaxing anonymous HTTP restrictions. File calls resolve both path representations in the remote workspace and refuse escaping links; full-access permissions cannot widen that workspace.

SSH filesystem effects are not assumed to avoid resources on another port. Conflicting database/port qualifiers or active production path rules without remote identity mappings are refused. Arbitrary commands, PTC, terminal streams and unknown protocol calls remain unconfined and are refused under active protection. This does not complete unrestricted execution on test servers. Connections close when local policy is revoked and never reconnect silently. SSH defaults to direct TCP. An explicit `proxy: { protocol, host, port, username?, passwordRef? }` routes this connection through a trusted HTTP(S) CONNECT proxy, independently of environment variables and the security-mode UI. Authentication requires a paired username and stored credential reference. The original SSH hostname is checked locally, one verified literal IP is sent in CONNECT, and the SSH fingerprint remains mandatory. Rules are rechecked after proxy credential lookup and tunnel establishment; refusal, cancellation or a changed rule never triggers a direct fallback. Proxy TLS uses the system trust store. This route does not provide payload capture or remote resource mapping.

Mount `./rea` instead of the ordinary REA root service, keeping the existing `rea/agent` consumer. The provider checks direct connections before native spawn and checks each queued external call before dispatch. It refuses execution under the same conditions as `./subprocess`, including protected owner files; engine names or read-only MCP annotations do not establish target confinement. Local policy changes or owner withdrawal close existing processes and settle their calls before releasing rule resources. This opt-in refuses unsupported native execution; it does not sandbox REA or protect independently configured MCP clients.

Mount `./mcp` instead of `mcp-client` for each guarded server, using its existing settings and the `tools` service. Stdio and HTTP MCP are refused before connecting while the server's effects cannot be bounded under active target or owner-file protection. Every reconnect, discovery, tool call and resource request rechecks the executor policy; read-only annotations are not proof of safe effects. Revocation closes the SDK-owned processes and transport, cancels requests and stops reconnects. If closure cannot be confirmed, the error remains visible and the rule owner is retained pending acknowledgement. This is admission and revocation, not a native-engine sandbox or an HTTP MCP target adapter.

Mount `./sqlite` with `databases: [{ name, path }]` for existing local SQLite files. It requires native `DatabaseSync.setAuthorizer`; unsupported runtimes fail activation. Optional `./sqlite-agent` uses `tools` and `sandboxPolicy` to expose `database_query`; permissions below full access force read-only queries. SQL selects configured names, not paths. Full protection refuses before helper allocation; audit uses a native read-only connection. Test batches execute atomically with bound parameters, stock SQLite functions and FTS. Attachments, extensions, journal changes and caller-controlled transactions are refused by the engine authorizer.

Defaults are 30 s execution, 1 s lock wait, 1000 rows, 1 MiB result, 64 KiB input, 64 MiB SQLite heap, 1 s termination grace and four retained requests, including helpers whose shutdown is unconfirmed. A managed private helper permits terminating an infinite synchronous query. Results preserve duplicate columns, blobs, large integers and nonfinite reals. Keep the installed runtime and helper outside Agent-writable paths. This adapter does not isolate privileged external file replacement or other database protocols.

Before commit, the executor rechecks paths, native file identity and rules, retaining the registry snapshot until native completion. Other policy writers receive `busy`; WAL registries are refused for retention because WAL readers do not exclude writers. Pre-authorization changes roll back the batch. Pre-authorization cancellation or timeout sends no commit permission; uncommitted journal recovery may be needed. After authorization, cleanup waits for confirmation. `SQLITE_OUTCOME_UNKNOWN` requires inspection and forbids automatic replay.

SQLite checks configured and canonical journal paths. The main database must have one hard link, checked before launch and commit; multiple names can select different journals ([SQLite guidance](https://sqlite.org/howtocorrupt.html#_multiple_links_to_the_same_file)). To migrate a hard-linked binding, stop clients, create a consistent SQLite backup at a unique filename, and update `databases[].path` and its path rules. Do not rename an active database or discard recovery journals. Confirmed commits followed by cleanup failure report `SQLITE_COMMITTED_CLEANUP_FAILED` and must not be replayed. `SQLITE_CLEANUP_FAILED` states that commit permission was not sent.

Mount `./postgres` with `targetProtection` and `credentials` for fixed PostgreSQL catalogue audits. Bind `databases: [{ name, hostname, port, database, username, passwordRef, caPem? }]`; port defaults to 5432. Credentials are resolved on each operation. TLS certificate and original-hostname verification are mandatory; a private CA can be supplied as PEM. Use direct native PostgreSQL endpoints: poolers or proxies that remap databases are unsupported. Network rules do not discover the server's data files or aliases; bind those separately.

Optional `./postgres-agent` registers `database_inspect` with only a configured binding name. It returns verified database/login/version, table names/kinds/RLS flags and selected security settings, never user-table rows or arbitrary SQL. Full protection refuses before TCP or authentication. Audit uses executor-owned `pg_catalog` queries in a read-only transaction, with identity verification before catalogue reads. PostgreSQL [READ ONLY does not prohibit every disk write](https://www.postgresql.org/docs/current/sql-set-transaction.html); it is not a sandbox for model-generated SQL. Test writes and other network database engines remain unsupported.

PostgreSQL resolves DNS once per operation, binds one checked literal address, preserves the original TLS name and never retries another address. Policy is checked after credential resolution and before/after queries. Cancellation, timeout or provider withdrawal destroys the owned socket and waits for native closure before releasing rules. Default limits are 30 seconds, 1000 rows per query, 1 MiB total decoded result and four pending operations. Output limits do not bound PostgreSQL wire-frame allocation; use only trusted owner-configured servers. Errors return stable credential-free codes; no operation is automatically replayed.

Mount `./browser` instead of `dsh-browser-use`, keeping the chosen Playwright MCP, Chrome DevTools MCP or Stagehand provider. All three resolve mandatory execution permission before their native acquisition and recheck queued calls. Protection revocation closes resources and retains rules through native settlement; missing policy withdraws this registry and its providers. The refusal conditions match `./subprocess`. This adapter provides admission and revocation, not per-target browser isolation. Test labels do not confine arbitrary browser file, network or detached-process effects; ordinary unguarded compositions retain their existing behavior.

Mount `./cordis` instead of `dsh-cordis-host-runner` to refuse dynamic Host activation, panel activation, Client source delivery and handler invocation before code runs. Definitions and read-only inspection remain available. This provider refuses even when target rules are disabled: Host VM and page code cannot be terminated or confined reliably after a later policy change. Full-access and Client approval do not override it. An explicit trusted configuration change may replace the provider; it never falls back automatically.

Mount `./plugin-manager` instead of `dsh-plugin-manager` to retain local plugin/bundle discovery while requiring a live, authenticated owner Remote invocation for profile changes, version exemptions, installation, removal, registry inspection and package lookup. Owner settings continue to use the existing methods. The model tool explicitly clears inherited Remote identity, including under full access. Direct in-process calls without an owner invocation are refused. Both adapters require `targetProtection`; owner withdrawal also disables them and cached references reject. These are management admission controls, not a sandbox against arbitrary trusted Host plugins or an owner who deliberately replaces the protected composition.

Optional `./ptc` replaces `dsh-ptc-runtime-node` with a fresh QuickJS WebAssembly interpreter per call in a private Node Worker. It implements the existing `run_code` consumer, accepts an async TypeScript function body with erasable types, and exposes only declared async bindings and console output. It has no Node, process, native file/network access, timers or module loading. QuickJS allocation, stack, source/output/message sizes, queued calls, Worker count and deadlines have validated configuration fields. The ordinary Node PTC provider remains available in other compositions.

Bind every side-effecting function to the appropriate protected provider; the interpreter does not confine arbitrary trusted Host functions. Bindings retain their own cancellation and cleanup ownership. `run_code` aborts and drains started tool calls before returning. Policy revocation stops the Worker. Unconfirmed native shutdown throws `PTC_SHUTDOWN_UNCONFIRMED`, rejects further calls on that runtime and retains its rule lease and capacity until actual exit; restart the Host before reuse. This optional provider is not yet part of the default product and does not implement arbitrary target-confined commands.

QuickJS and [quickjs-emscripten](https://github.com/justjake/quickjs-emscripten) provide the MIT-licensed interpreter and WebAssembly bridge; `quickjs-emscripten-core` and `@jitl/quickjs-wasmfile-release-sync` are pinned to 0.32.0. Source and compiled Worker paths are verified separately.

## Implementation

<details>
<summary>Maintainer details</summary>

The SQLite format has monotonic `SCHEMA_VERSION = 3` and application ID `DSTP`. Valid version 1 and 2 registries upgrade transactionally without changing their preferences or revision; earlier code refuses version 3 on reopening, so downgrade requires restoring a pre-upgrade backup. Version 1 cannot contain paths and versions before 3 cannot contain aliases. Format, application identity and preferences are read in one SQLite snapshot; every operation checks them again. Writes compare the caller's expected revision in a transaction. Lock conflicts return `busy` without committing, and damaged data is preserved.

The HTTP consumer checks before resolution and before each connection, including redirects. The resolver retains CNAMEs and A/AAAA records from the same answer packets, validates transaction/question identity, follows bounded chains and uses TCP for truncated UDP replies. Hosts-file aliases and localhost are handled without external lookup. The shared transport pins the validated addresses and retains NAT64 IPv4 aliases for rule and country checks. Unrelated answer records never become destinations.

The decision uses current rules and rechecks their revision after asynchronous resolution. Local rule changes and country-provider replacement cancel requests using the old generation; this does not roll back effects already sent. HTTP and file executors retain the rule owner's resources through native operation settlement and cleanup. Proxy address facts without literal binding remain unknown. Registry failure, cancellation and service disposal cannot authorize a connection.

The local file adapter checks direct service calls and rechecks writes inside the file lock, before staging and immediately before atomic publication. A change from another registry connection can refuse publication and remove staging residue. Withdrawal aborts admission and waits for active I/O and source iterators to close before releasing dependencies. The local filesystem's external-process path race remains: path revalidation does not provide kernel isolation against a hostile process replacing ancestors between validation and a syscall. Partially created parents or earlier completed effects are not rolled back.

File identity uses BigInt device and inode values without rounding Windows identifiers. Existing files with unavailable identities cannot be declared unrelated to protected files. Prospective absent files remain a separate state. DNS evidence is keyed by canonical hostname so one resource's aliases cannot overwrite each other's bindings; selectors outside the current port or database scope do not trigger DNS queries.

Native execution can obtain detached file constraints with `nativeFileConstraints()` and compile explicit grants with the internal native-file policy builder. Directory scans include linked targets and complete Windows hard-link names; budgets, cancellation and changing directories refuse incomplete policies. Readonly production restrictions remain stronger than nested writable grants. The optional native command provider consumes these constraints; default product integration remains separate.

The private native worker loads only after its bootstrap identity is checked and assigned to an independently observed Job. Its bounded framing separates target stdout, stderr, descriptor-seven traffic, direct exit, stream EOF and inner-range exit; output bytes cannot become lifecycle messages. Targets receive the explicit request environment. The worker reuses the strict Windows Job runner for the command range, so direct exit preserves surviving descendants. After that inner range and its streams close, the worker exits naturally; the host must still confirm the outer Job empty before releasing protection. Acceptance announces available launch pipes, not whether target execution has started. Transport and observation failures terminate work and remain failures. Source and compiled paths are verified through the optional `Subprocess` provider; full protocol coverage and default product integration remain unfinished.

The internal Host handle starts a fixed trusted broker inside a strict outer Job before any MXC SDK call. Cancellation therefore covers SDK-created descendants even before the SDK returns a handle. Preparation resolves the complete target environment after allocating its private gateway; the broker uses a separate scrubbed environment. Startup has a caller-configured deadline; target streams reuse bounded collection and spill, while bounded broker diagnostics stay separate. Rule and proxy release waits for independent outer-range closure; an unknown outcome retains protection and reports failure. The compiled Host/broker/worker chain is verified on Windows Node 24. It backs the optional `./subprocess-native` provider; the default product still needs integration.

The internal native gateway binds loopback for one retained rule revision. HTTP preserves methods and bodies, validates Host, resolves names with their aliases and pins every admitted hop. Private targets need an exact owner-selected test-server name or IP. Redirects return to the caller, whose next request receives fresh checks. CONNECT checks both the named endpoint and literal address without claiming application names or database identity; ambiguous domain, regular-expression or database rules refuse opaque traffic. Optional upstream failures never trigger direct fallback. Closing joins sockets before releasing the rule revision.

The source and compiled Windows chain verifies test access, zero production connections and `EACCES` for direct egress outside the gateway. MXC 1.0.1 requires `ingress.default=allow` for its identityless proxy; this does not establish complete inbound isolation. Arbitrary TLS/application-name inspection, strict inbound peer isolation and default product composition remain unfinished.

`retainNativeExecution(revision, stop)` holds the checked registry revision until the caller confirms that its process range and network transports have closed. Concurrent commands share the retained revision. Owner configuration changes stop every admitted native execution before committing; failed shutdown keeps admission disabled and the old revision retained. An explicit owner retry rechecks shutdown without replaying the command. Country-source changes also revoke native execution. A release callback is a physical-closure acknowledgement, not a general cleanup callback.

The independent registry does not change Session record types. Durable execution-audit events and SDK projections belong to the remaining audit integration. The archived development draft is not a supported database predecessor and is never silently imported.

</details>

<a id="model-experience"></a>
## Model Experience

The root service adds no model request. Optional `./sqlite-agent` adds `database_query`, and `./postgres-agent` adds `database_inspect`; results and typed refusals use normal tool logging. Other adapters change affected tool results. Effects come from the executor, never a model's safety claim.

#### KV Cache effect

Only optional database tools add prompt schemas. No auxiliary model is called.

<a id="known-limitations-and-deferred-work"></a>
## Known Limitations and Deferred Work

Only explicitly composed guarded providers are covered. Structured file removal and renaming support local files and the matching SSH helper, not directory trees. Remote hard-link/mount identity, arbitrary PostgreSQL/test SQL, other database protocols, constrained commands, and browser/MCP/REA native execution still need adapters. Deployments must keep the remote runtime trusted and outside Agent-writable workspaces. Opaque proxy tunnels remain unsupported under protection; Security-mode UI routing and SSH payload capture remain separate work. Ordinary anonymous fetch still refuses private networks. DNS evidence cannot enumerate every hostname sharing an IP, and country data or CONNECT cannot attest physical forwarding. Default composition, owner UI, security-entry status and durable audit remain unfinished.
