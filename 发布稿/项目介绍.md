# DeepSeek Harness Uncensored：把开发、网安、逆向和写作放进一个桌面工作台

DeepSeek Harness Uncensored（简称 DSHU）是基于 DeepSeek Harness 的开源桌面智能体工作台。它内置了 dsh-purge Community 的破甲核心，也把工具和参考资料按任务分成四套。修代码时，助手可以进项目目录查文件、跑测试。换到写作模式，它读的就是你为这本小说选好的人物设定和文风样例。审查应用和分析二进制文件也各有专门的工作模式。

如果已经装了官方 DeepSeek Harness，也可以把 DSHU 装在同一台机器上。两者的程序、配置、会话和更新渠道各自独立。

## 四种模式，各自带什么工具

新会话默认使用「缺省」模式，发出第一条消息前可以自由选择。不同模式带着不同的工具、手册和资料，手册用到时才加载。发出消息后，模式默认锁定。侧栏会保留对应的颜色，几个项目同时开着，也能看出哪条会话在修代码，哪条在写稿。

> **【此处手动粘贴图片｜02-四种模式.png】**

**缺省模式**适合日常开发。比如搜索框连续提交两次，先发出的请求晚回来，覆盖了新结果。把项目目录选作工作区后，可以让 DSHU 找到更新结果的代码，做必要的修改，再跑一个让旧请求最后返回的测试。最后能对照改过的文件和实际运行的检查，判断问题有没有解决。只想查资料或听一段代码解释时，也可以直接提问。

**网安模式**适合在授权范围内做应用审查、配置检查和修复验证。一次审查常常跨好几个会话，最容易丢的是「上次查到了什么，还有哪条证据没补」。实验性的案件记录把目标、证据、发现和备注保存在工作区的 `.security/` 目录里。下次打开同一案件可以接着查，收尾时也可以生成 Markdown 报告。

**逆向模式**面向程序、文件格式和协议分析，内置 REA 6.9.0。拿到一份缺少格式说明的固件，可以先计算样本哈希、提取可打印字符串，再对照字节偏移整理文件头。下面的例子里，已经确认的字段用来写解码器，用途尚不清楚的字段单独列出。实验性的逆向案件可以把样本信息、证据和待验证的假设一起保存。

> **【此处手动粘贴图片｜03-固件分析.png】**

**写作模式**适合小说、剧本和长文。这个模式不加载终端和代码执行工具，工作区里的 `story/` 用来放创作资料。实验性的设定集可以记人物关系、时间线和已经发生的事，文风卡则可以留一段样文，说明对白和叙述的节奏。续写时只把勾选的资料交给模型。比如要写第七章，就可以带上第六章结尾的人物状态，让它写完正文后再单独检查前后是否接得上。

## 主任务继续跑，有问题随时问

跑长任务时，有时只想知道测试跑到哪了，有时又想把某个细节聊透。DSHU 给这两种情况各留了一个入口。

**随问**适合问一句就走。在主输入框发 `/btw 进度如何`，它能看到任务清单、最近调用的工具，连正在执行的那一步也算在内。回答显示在输入框上方的小卡片里。随问只有只读权限，主任务照常运行。

**旁问**适合来回讨论。比如主线已经起草了一份发布说明，你可以发 `/side 第二条能不能换成普通用户看得懂的说法？`。右侧会打开独立对话，每次提问前都会同步主线已完成的进展。你可以附图、追问、比较几种措辞。等选定一句，再回主输入框告诉它用哪一版。旁问记录单独保存，默认关掉标签也能回来接着聊。

## 这次对话花了多少，下次还能记住什么

DSHU 在侧栏显示账户余额，在会话底栏显示本次对话的费用。点开「设置 → 额度」，可以看本机采样的余额曲线。想控制长任务的开销，可以给 5 小时和 7 天分别设一个金额上限。这些限额默认关闭。开启后，只要下一次请求预计会超出其中一项，对话就会暂停。勾选「自动恢复」后，等各项额度都够用，任务会接着跑。界面费用是本地估算，实际扣费以提供方账单为准。

> **【此处手动粘贴图片｜06-余额曲线.png】**

另一个日常方便之处是**跨对话记忆**。例如「这个仓库统一用 pnpm」可以只记在当前工作区，而「写作时保留人物原有的称呼」可以限定在写作模式。以后新开会话，DSHU 会按范围检索相关记忆，也可以手动编辑或停用。这项功能仍在实验中，自动提炼默认关闭，开启后会额外调用模型。

输入框也支持预测。打字停下来时，如果灰色补全正好是你想说的，按 Tab 就能接上，什么时候发送仍由你决定。预测会调用当前模型并产生费用，可以在「设置 → 通用」里关闭。

## 下载与开始使用

项目以 GPL-3.0-or-later 开源。正式版 2026.11.23.0 提供 Windows x64、Linux x64 / arm64 和 macOS arm64 安装包。首次打开后，在「设置 → 模型」填写提供方和 API 凭据，选好模型，再新建会话。第一次试用可以从自己熟悉的项目开始，让它找出程序入口和测试命令，你很快就能核对它读到了哪些文件。
