# 受限原生命令：执行后端验收

属于目标保护 P2（09.04–09.08），不缩小原始测试目标完整执行、数据库及 P3 联动范围。当前仍为后台开发，默认产品没有加载完整保护或新的原生命令提供方。

## 已核实的候选

采用微软 [MXC 1.0.1](https://github.com/microsoft/mxc/tree/fda29ac63bc306b7f97f3b86b4b63d44f7f40cf2) 作为 Windows 执行隔离候选，源码与 npm 均为 MIT，Node SDK 要求 Node 24。只安装在独立验证目录，尚未加入产品依赖。Windows 26340.9843 实际探测到 base-container、拒绝路径和专用回环代理能力，无需修改宿主 DACL。没有运行 host-prep、UAC 提升或可见安装窗口，遥测未启用。

| 实际场景 | 观察 |
| --- | --- |
| 直接 IP/端口 allow，加 hostLoopback allow | **不满足要求**：同机未允许端口仍收到连接；不能用探测器返回可用证明该策略有效 |
| 专用代理模式，禁止直接出口 | 允许的代理端口收到 1 次连接，另一测试端口 0 次；原始 TCP 返回 EACCES |
| 只拒绝生产目录 | **不满足要求**：工作区内已有硬链接仍可读生产文件 |
| 生产目录与全部硬链接名称均拒绝 | 原路径、硬链接、目录 junction 均不能读；改名或再创建别名均失败 |
| 只读文件通过新硬链接写入 | 创建链接失败，文件内容不变 |
| 测试目录普通写入 | 成功写入；生产文件和只读文件经父进程复核内容不变 |

Node 初始化不能完全关闭 Win32k；验证使用容器级 UI 隔离、禁用剪贴板及输入注入，进程管道模式隐藏控制台。D 盘程序读取需要显式的祖先目录枚举权限；这不等同于授予祖先目录所有文件的读取权限。尚未把这些探测参数作为产品默认值。

SDK 来源与原始证据在 `.dsh-build/mxc-npm-1.0.1.json`、`.dsh-build/mxc-reference-20261102` 和 `.dsh-build/mxc-probe-20261102`。后者的 `probe.json`、`execution.json`、`execution-proxy.json`、`execution-aliases.json`、`execution-readonly-alias.json` 与 `verified-results.json` 保留通过与失败结果。验证脚本同目录；只操作其 `execution-*` 临时目录与本机临时端口，不读写用户生产目标。

## 接入顺序

- [x] 核验 SDK 许可、版本、原生能力与真实拒绝效果，保留不能使用的直接出口配置负例。
- [x] Windows 原生硬链接与卷挂载名称加入现有文件保护；逐项验证文件 ID 和链接数，失败不当作无别名。其他平台继续拒绝无法确认的链接。
- [ ] 从所有者文件规则生成原生只读/拒绝列表，包含目录后代、所有硬链接、规则库、凭据及辅助数据；不能直接把路径列表交给 MXC 就宣称完成。
- [ ] 建立受保护目标代理，并让命令只获得该出口。代理在所有命令及后代退出后才释放；不能把代理地址当作最终目标。
- [ ] 以真实 Subprocess 提供方接入标准输入输出、取消、后代回收及 PTY。按已验证能力选择平台，失败不回退普通进程；不使用 SDK 内部接口或 argv 逃生路径。
- [ ] 规则修改在运行中收紧权限时，先终止并确认相关原生执行范围退出，再释放旧策略；其他规则库连接不能提前提交冲突规则。
- [ ] Windows 原生/编译入口、Linux 与 macOS、真实 profile/Session 回放、MCP/REA/浏览器消费者及产品装配分别验收。

原数据库任意 SQL、远端路径/挂载身份、全部原生入口和审计仍未完成。此候选的通过样例不能替代完整后端交付；不修改 armor 文本，不通过关闭保护来通过测试。
