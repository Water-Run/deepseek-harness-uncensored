## PTC Worker 发起归属（2026-11-06）

PTC Worker 的 Host 回调可从完整发起调用继承准确的存活 Agent；无作用域的原生提供方据此沿用网安独立上游及流量记录，不依赖审计开关。明确无 Agent 的工具派发清除外围发起者；仅绑定审计编号不会建立代理身份，撤销或同编号替换后的发起 Agent 会被拒绝。现有明确 Agent 作用域仍优先。

真实 Worker 的改前负例走了静态备用代理；修复后测试请求通过独立上游，生产目标零连接。两个 Worker 在回调屏障处同时进入，流量分别归入各自会话。关闭代理等待 Worker 委派的原生范围及传输结束。相关回归 72 项分批通过；编译公开入口另验证命令、ConPTY 与 Worker，七条捕获流量及私有目录回收，回执 `.dsh-build/native-worker-built-20261106-result.json`。这不等同于任意 Worker 或跨进程来源接入完成。

## 网安上游与原生捕获（2026-11-06）

已注册 Agent 的原生命令与 ConPTY 在网安独立代理开启时使用该上游，并共享现有流量页、暂停、脱敏与正文限制。部署配置的静态代理用于未覆盖调用；已覆盖的准入失败不回退直连。只有审计会话而没有实际执行 Agent 的通用调用不取得网安捕获租约，其他 Worker 的接入继续保留。

## 已核实的候选

采用微软 [MXC 1.0.1](https://github.com/microsoft/mxc/tree/fda29ac63bc306b7f97f3b86b4b63d44f7f40cf2) 作为 Windows 执行隔离候选，源码与 npm 均为 MIT，Node SDK 要求 Node 24。已作为目标保护包的固定运行依赖，正式命令提供方尚未装配。Windows 26340.9843 实际探测到 base-container、拒绝路径和专用回环代理能力，无需修改宿主 DACL。没有运行 host-prep、UAC 提升或可见安装窗口，遥测未启用。

| 实际场景 | 观察 |
| --- | --- |
| 直接 IP/端口 allow，加 hostLoopback allow | **不满足要求**：同机未允许端口仍收到连接；不能用探测器返回可用证明该策略有效 |
| 专用代理模式，禁止直接出口 | 允许的代理端口收到 1 次连接，另一测试端口 0 次；原始 TCP 返回 EACCES |
| 只拒绝生产目录 | **不满足要求**：工作区内已有硬链接仍可读生产文件 |
| 生产目录与全部硬链接名称均拒绝 | 原路径、硬链接、目录 junction 均不能读；改名或再创建别名均失败 |
| 只读文件通过新硬链接写入 | 创建链接失败，文件内容不变 |
| 测试目录普通写入 | 成功写入；生产文件和只读文件经父进程复核内容不变 |

Node 初始化不能完全关闭 Win32k；验证使用容器级 UI 隔离、禁用剪贴板及输入注入，进程管道模式隐藏控制台。D 盘程序读取需要显式的祖先目录枚举权限；这不等同于授予祖先目录所有文件的读取权限。尚未把这些探测参数作为产品默认值。

SDK 来源与原始证据在 `.dsh-build/mxc-npm-1.0.1.json`、`.dsh-build/mxc-reference-20261102` 和 `.dsh-build/mxc-probe-20261102`。后者的 `probe.json`、`execution.json`、`execution-proxy.json`、`execution-aliases.json`、`execution-readonly-alias.json` 与 `verified-results.json` 保留通过与失败结果。验证脚本同目录；只操作其 `execution-*` 临时目录与本机临时端口，不读写用户生产目标。

## 原生回收约束

MXC 1.0.1 的 BaseContainer `kill_process_tree` 在 Job 未及时清空时只写 stderr 并继续，故 SDK `wait()` 成功本身不能作为所有后代已退出的充分证据。当前真实用例用预先持有的内核进程句柄确认已知后代退出后才释放修订。正式提供方必须拥有可独立查询的执行范围，或使用具备严格关闭确认的受支持接口；不能解析 stderr 当作可靠状态，也不能在未确认关闭时释放旧保护。该缺口尚未绕过或标记完成。

`dsh-win32-process` 已实现独立 Job 所有者。启动者核对随机标识和 SDK PID，所有者再打开进程并核对精确创建时间；分配成功后才发送目标工作。引导程序必须在此之前既不创建子进程，也不加入其他 Job；启动环境不得继承 NODE_/TSX_ 预加载设置。首次原生回归使用 tsx 引导未能构造“根退出、后代仍活动”的场景，改用无预加载的测试引导后通过，失败日志仍保留。

Windows 原生与 MXC 共 6 项通过，两组独立进程各 6 项通过；完整相邻回归 87 项通过，补充的计时器故障测试另通过。Linux 23 项通过、3 个 Windows 专属跳过；可移植逻辑覆盖率四项均 100%。省略 Job 分配的负对照按预期失败，编译导出实际保留后代直到终止。证据为 `.dsh-build/observed-job-*-20261102.log`。正式提供方仍须接私有运行时入口、标准流背压、目标代理、取消及 PTY；不能把这些基础验证改记为完整命令后端已交付。
