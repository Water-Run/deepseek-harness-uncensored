## 统一执行规则

- 用户生产规则优先：完全保护优先于只读审计，两者均优先于测试例外；测试例外只豁免它精确覆盖的对象，不覆盖同一次操作的其他对象。
- 命中规则以规范化后的逻辑地址和实际执行地址共同判断。缺失端口、数据库名、路径身份或目标解析结果时，不能把信息不足当作不匹配。
- 只读是执行器能力：HTTP 方法、命令文本、SQL 首词、MCP 声明或模型给出的“安全”标签均不足以单独证明无写入效果。
- 任意 shell、常驻终端、远端命令、MCP/REA 和浏览器必须有可验证的目标约束；接入前按不支持或无法确认拒绝受保护操作，不能把提示词、代理环境变量或命令字符串扫描宣传成进程隔离。
- 数据库规则须区分实例、端口、库名及本地数据库文件；不明数据库不能借用同机测试库的例外。未接入的协议明确拒绝，不宣称所有数据库已经受保护。
- 大陆判定区分域名标签、实际解析地址及数据来源；`.cn` 后缀不等同于完整的大陆 IP 覆盖。数据缺失、过期、DNS 失败和别名变化必须有确定行为。
- “完全权限”、普通工具批准、模式切换、子会话和模型建议不能取消用户的目标保护规则；修改规则由应用所有者完成。
- 必需保护与规则提供方的可用性分别记录。规则服务失败、重载或退出时，执行入口必须停止新的准入，不能因监听器消失回落到“未配置策略”的放行分支。

## 必须有的验收证据

| 场景 | 验收结果 |
| --- | --- |
| 生产完全保护 | 本机测试监听器没有收到连接/请求；受保护文件哈希不变；数据库没有执行语句 |
| 生产只读审计 | 明确的只读操作完成；写入、带副作用操作、未知命令/协议被拒绝 |
| 测试例外 | 对精确测试目标的完整操作成功；同主机其他库、其他端口、生产别名和多目标操作仍受保护 |
| 重定向/别名/路径 | 跳转、DNS 回答变化、IPv4 映射 IPv6、IDN、符号链接不能改变最终决策 |
| 直接调用及包装 | 绕过工具面板、普通审批、工具重试、子会话、PTY、SSH 或 REA 不能绕过执行检查 |
| 途中修改/取消 | 旧版本许可失效；被拒绝或取消的操作没有后续副作用；资源和临时文件完整释放 |
| 重启和故障 | 规则恢复；损坏、未知版本或后端不可用不静默放行；界面显示真实状态 |
| 日志与模型 | 审计可回放且不泄露凭据；模型输入可复原；不改写现有 armor 文本 |

所有破坏性验收只对本轮创建的临时文件、进程、监听器和测试数据库执行，不使用用户正在运行的生产环境。仅有设置开关、匹配单测或文档不算完成对应交付项。

## 已发现的缺口

旧草稿将 `.cn`/中文域名后缀当作大陆判定，未覆盖 IP 位置；操作效果仍由模型提供；当前子进程沙盒主要处理文件写权限，没有提供按目标隔离的完整网络执行能力。HTTP 直连已有解析地址固定机制，但代理路径把解析交给上游，必须单独解决目标绑定。旧草稿不能直接恢复到运行时并标记完成。
