## 交付范围待决

本轮已确定先合入通用内核、写作和额度，三部分按下表独立验收。全产品替换还涉及现有网安与逆向模式的装配和子代理执行。自动化攻击、漏洞利用及其代理接续属于本次无法协助迁移的缺口。当前版本继续提供已发布的产品组合。在批准变更产品范围之前，应保留当前发行基线。

产品维护者需决定新内核候选的模式清单。可独立验收的候选包含通用与写作模式，以及经确认的只读分析、诊断或修复功能。若采用缩小范围的候选，升级指南须逐项说明可用入口、旧会话可读性、受影响设置与替代操作；历史会话不能被静默改成另一种模式。若要求原有产品组合整体兼容，该范围决策继续阻塞完整升级与发行。

Windows x64 的 Electron 44.11.5 压缩包 SHA-256 为 `2938040ee81382bb8a99954425a316fee17f23d55f5be0ef413275f7e793c8af`，与冻结依赖附带的校验值一致。用其中的可执行文件运行 SQLite 内存查询和 Zstandard 压缩往返均成功。实际内置 Node 为 24.22.3，模块 ABI 为 149，SQLite 为 3.54.1，Zstandard 为 1.6.0。

将已核验的 Electron 可执行文件作为第三个参数传给资料验证脚本，写入阶段仍使用正式版源码和独立 Node，随后两个读取阶段使用 Electron 的 RunAsNode 模式。验证在测试进程内核对 Electron 版本。写作资料、工作区、额度及会话的 4 项场景在三个进程中均通过，备份的 15 份文件摘要一致。此项覆盖桌面运行时的资料读取，已安装应用的启动、外部原生模块装载和安装器升级另行验收。

```sh
node scripts/verify-kernel-released-data.mjs <正式标签检出目录> <已还原的候选目录> <Electron可执行文件>
```

Windows 终端的正常退出还有一项生命周期修复。旧候选能收到子进程的完成状态并释放 Cordis 实例，但输出转发线程继续持有管道。独立宿主打印出释放完成后，45 秒内仍未自行退出。当前候选树为 `a9ac108edcc3213ec570cf4959a26f6fb59db443`。输出管道关闭时，node-pty 释放其转发线程。回归通过真实的子进程服务依次运行三个命令，核对普通输出、无输出时的退出码 7 和连续 256 行末尾输出，再等待宿主自然退出。在同一 Windows x64 机器上，Electron 44.11.5 的真实 Cordis 宿主也已正常退出，单次实测 4.5 秒。冻结依赖中 node-pty 仍为 1.2.0-beta.15，锁文件记录新的补丁摘要。Windows 宿主退出测试共 5 项通过，1 项仅适用于其他系统。当前树的 8 项产物构建及 2 项聚合类型检查通过。从主线补丁新还原的独立目录完成冻结安装，终端自然退出回归通过，并用 Electron 重新核对了正式版的 15 份资料。

在还原的候选目录运行下列命令可复验。用例本身只在 Windows 运行，宿主的完成条件包含父进程自行退出。

```sh
pnpm exec vitest run packages/subprocess/subprocess-local/tests/process-exit.spec.ts -t "exits after draining"
```

### Windows 安装器编译工具链

候选打包预检原先在已安装 Visual Studio Professional 2026 Insiders 的机器上报告缺少 C++ 工具。DSHU 的安装器使用 x86 辅助 DLL，打包预检、编译脚本、控制台信号测试与打包运行器现在都使用 `vswhere -latest -prerelease` 查找具有 x86/x64 C++ 组件的实例。使用独立候选目录及本地测试配置运行 `win-x64 --unsigned --dir --check`，预检通过。校验树为 `277c974d09c92160d9528e2d4b1335084066b3ea`。

用同一工具链执行 `prepare-windows-installer.ps1 -TestProgress`，实际编译了 `window-frame.dll` 和五个测试程序，卸载资料、进度、呈现、绘制与解包报告检查通过。使用冻结依赖指定并核对 SHA-256 的 Electron 44.11.5 执行 Windows 控制台测试，SIGINT 和 SIGBREAK 均成功送达。以上验证覆盖安装辅助程序与控制台信号，完整安装和旧资料原地升级仍须在打包产物上验收。

### 会话费用入口

在候选树 `8ffb1ff8eb3926a3b079bbb7641f105d05d0d31b`，会话输入框下方可展开当前会话的累计费用和各个已启用额度窗口的占用。已记录的记忆提炼计入所属会话，费率或用量不全时显示已知费用下限。账户余额历史独立于这条累计费用曲线。组件回归核对了可用窗口、权限撤销、弹层焦点、原样本精度和按实际尺寸计算的虚线阈值。

在实际 Web Host 中，用本地适配器生成两笔写作用量，再从另一条会话切换回来。Chromium 显示两条会话各自的 1.00 元和 0.000216 元，写作费用展开后有两个采样点。1280 与 390 像素视口内均可用 Home、End 检查端点，Escape 将焦点返回原按钮。同一场景还检查双窗口暂停、恢复、写作资料撤回及恢复后只发一次请求。候选的 8 项产物构建和 2 项聚合类型检查均通过。

### Windows 桌面目录包

树 `277c974d09c92160d9528e2d4b1335084066b3ea` 的 `win-x64 --unsigned --dir` 生成了带 ASAR、内置 Electron、离线依赖和 Office 运行时的应用目录。测试使用隔离的策略地址。打包最后的 Office 检查在深层构建目录中触发 Windows 文件名过长错误。用同一个包的 Python 导入 `lxml._elementpath`，深层目录退出码为 1；原样复制整个应用到较短目录后退出码为 0。

在较短目录对实际 EXE、ASAR 和资源执行 `smokePreparedRuntime`，原生依赖、终端、离线插件安装与移除、Office 技能加载、DOCX/XLSX/PPTX 转 PDF、图像渲染及表格重算均通过。长路径安装仍须由 Windows 维护者用实际安装器复验；本地未签名目录不能充当正式发行包。

### macOS 首装与应用内更新

已核对 [2026.11.23.0 发行附件](https://github.com/Water-Run/deepseek-harness-uncensored/releases/tag/v2026.11.23.0)。手动安装入口指向 DMG。线上 [macOS 更新索引](https://github.com/Water-Run/deepseek-harness-uncensored/releases/download/v2026.11.23.0/latest-mac.yml) 的 `files` 与 `path` 均指向同一个 497,240,952 字节的 ZIP，附件大小与索引相符。该已发行版本的 macOS 更新器选择 ZIP，并排除 DMG。移走当前 ZIP 会中断该索引的下载。[更新器实现](https://github.com/electron-userland/electron-builder/blob/master/packages/electron-updater/src/MacUpdater.ts)

DSHU 主线的过渡版使用 `deliver:github --bridge` 整理五个安装包、四个 `latest*.yml` 索引和一个 macOS ZIP。以后常规发行只上传五个安装包。每个公开正式版按发布顺序接替 GitHub Latest。过渡版仍为 Latest 时，旧安装可以在应用内升级；曾手选开发版的用户须先切回正式版。错过窗口的旧安装需要手动安装一次当前版本。

新版查询本仓库最新正式 Release，按标签比较日期版本，核对附件的固定标签地址、大小和 GitHub SHA-256，并用正文携带的 SHA-512 校验下载。macOS 从校验后的 DMG 在本机准备 Squirrel.Mac 所需的归档。Windows 上已重放五个平台目标，验证旧索引、五附件发行、签名失败与卸载卷失败，以及冻结更新库的本机 HTTP 归档交接。正式签名安装、重启和资料保留仍需在各目标平台验收。候选内核使用独立验证壳，产品打包时需接入主线桌面更新入口与 DSHU 日期版本。[发行整理说明](../../apps/desktop/README.zh.md)

## 已有会话兼容性缺口

节点 3 另有一项已有的兼容性缺口。`verify-persistence-changes` 报告历史事件 `target/admission` 的 `peers` 和 `target` 两个必填字段尚未声明。与上述 DSHU 基线逐项比对，当前目录中的持久化根、类型摘要和节点相同，只有三条类型的源代码行号移动。维护者需用含旧事件的资料副本验证读取与重放，按[持久化规则](../persistence/README.md)补齐真实兼容决定，并复跑目录及变更声明检查后再验收内核升级。
