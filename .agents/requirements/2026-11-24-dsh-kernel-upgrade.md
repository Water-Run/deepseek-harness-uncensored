# DSHU 内核升级计划

## 交付范围待决

本轮已确定先合入通用内核、写作和额度，三部分按下表独立验收。全产品替换还涉及现有网安与逆向模式的装配和子代理执行。自动化攻击、漏洞利用及其代理接续属于本次无法协助迁移的缺口。当前版本继续提供已发布的产品组合。在批准变更产品范围之前，应保留当前发行基线。

产品维护者需决定新内核候选的模式清单。可独立验收的候选包含通用与写作模式，以及经确认的只读分析、诊断或修复功能。若采用缩小范围的候选，升级指南须逐项说明可用入口、旧会话可读性、受影响设置与替代操作；历史会话不能被静默改成另一种模式。若要求原有产品组合整体兼容，该范围决策继续阻塞完整升级与发行。

## 验收记录

在 Windows x64 的独立目录导出目标提交，使用上表工具链运行 `pnpm install --frozen-lockfile` 成功。pnpm 验证了锁文件的 1,770 条依赖策略记录。上游 `subprocess-local` 解析到的 `node-pty` 已通过 ConPTY 创建本地进程，子进程退出码为 0。锁文件中的 Electron 为 `44.11.5`，包声明的 ABI 为 149，内置 Node 版本和原生模块装载结果留到候选安装器验收。

在同一目标提交执行 `pnpm run build`，10 项检查全部通过，用时 411 秒。Host、客户端、桌面和 Web 产物均完成构建，两端聚合类型检查通过。构建记录包含 383 个客户端产物。此结果对应上游标签。DSHU 源码仍声明 `0.2.2-rc.5`，新内核安装器待构建和验收。

### DSHU 主线的会话读取

DSHU 已采用目标标签的 `Session` 实现、`SurfaceManager`、日志验证器和分叉错误类型。会话查询、JSONL 代际校验与当前格式目录使用同一个 `validateSessionLog`。持久化格式仍为 v4，已发布的格式代际保留原样。目标标签的 45 项日志测试覆盖借用与接管两种输入、非法序号、继承切点和旧头信息。对照旧主线运行时 45 项失败，移植后通过。DSHU 的持久化目录仍有 731 条类型记录，此节点只移动来源行号。

### 固定标签候选

通用和写作候选直接基于 `4b399c39a6d1479cd84ca591b4d7c88e24d38a96`。在独立 Windows x64 目录运行候选的额度测试，6 个文件、50 项通过。写作及上游 SQLite 持久化测试共 306 项通过、11 项跳过。当前候选对历史请求费用的估算覆盖有用量记录的回答和重试。DSHU 特有的记忆提炼费用、旧版完整资料库原地升级、桌面安装器以及 macOS/Linux 平台仍须独立验证。全产品交付前按节点 3 至 6 完成这些检查。

## 已有会话兼容性缺口

节点 3 另有一项已有的兼容性缺口。`verify-persistence-changes` 报告历史事件 `target/admission` 的 `peers` 和 `target` 两个必填字段尚未声明。与上述 DSHU 基线逐项比对，当前目录中的持久化根、类型摘要和节点相同，只有三条类型的源代码行号移动。维护者需用含旧事件的资料副本验证读取与重放，按[持久化规则](../persistence/README.md)补齐真实兼容决定，并复跑目录及变更声明检查后再验收内核升级。

## 回退与接手

每个节点开始前记录输入提交、锁文件和运行时版本。数据迁移与安装验证使用已有资料的副本，并保留升级前可启动的安装包及对应完整资料备份。失败时保留候选日志，用旧安装包和升级前资料副本复验；已经升级过的 SQLite 不能交给旧版直接写入。对已推送节点采用后续修复或回退提交。[已发布数据格式状态](../persistence/status.md)

下一位维护者确认候选模式清单后，可从节点 2 开始集成，并在桌面候选中补验 Electron 运行时。逐项附上提交、执行命令、产物摘要及待验平台，在[交付清单](../TODO.md)记录实际内核版本和首个未通过节点。
