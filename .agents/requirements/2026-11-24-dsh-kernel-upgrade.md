# DSHU 内核升级计划

## 目标与当前进度

将 DSHU 的通用会话、写作、额度、Web 和桌面载荷升级到 DSH `0.2.3-alpha.2`，并能从已发布的 DSHU 副本保留数据升级。目标是上游预发布版本。2026-11-24 已核对官方发布、上游标签和默认分支，并完成只读试合并。产品源码和安装包的内核升级均待完成。[官方发行](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.3-alpha.2)

| 核对项 | 基线与结果 |

| DSHU 基线 | `main` 的 `e89e7e7aed`，内核 `0.2.2-rc.5`，上游提交 `9c2670d3bce5275e0d1610272958121af87787bb`。当前内核身份见 [product.json](../../product.json)。 |
| 目标 | `dsh-v0.2.3-alpha.2` 与当日上游 `master` 均为 `4b399c39a6d1479cd84ca591b4d7c88e24d38a96`。发版前再次核对固定标签。 |

在有这两个提交和目标标签的仓库运行下列命令，可复算基线并取得逐文件冲突清单。最后一条首行给出试合并树，其余行是冲突路径，退出码 1 表示存在冲突。开发节点陆续推送后，另用当时的 `HEAD` 重算实际集成范围。

```sh
git merge-tree --write-tree --merge-base=9c2670d3 --name-only --no-messages e89e7e7aed dsh-v0.2.3-alpha.2
```

## 交付范围待决

通用内核、额度与写作可以按下表独立验收。全产品替换还涉及现有网安与逆向模式的装配和子代理执行。自动化攻击、漏洞利用及其代理接续属于本次无法协助迁移的缺口。当前版本继续提供已发布的产品组合。在批准变更产品范围之前，应保留当前发行基线。

产品维护者需决定新内核候选的模式清单。可独立验收的候选包含通用与写作模式，以及经确认的只读分析、诊断或修复功能。若采用缩小范围的候选，升级指南须逐项说明可用入口、旧会话可读性、受影响设置与替代操作；历史会话不能被静默改成另一种模式。若要求原有产品组合整体兼容，该范围决策继续阻塞完整升级与发行。

| 6. 发行决策 | 汇总每个目标的通过、失败与待验项，记录来源标签、分支提交、许可材料、升级指南与恢复步骤。 | 维护者确认范围与平台验收后再发布。源码推送、安装器构建和公开发布分别记录。 |

## 回退与接手

节点 3 另有一项已有的兼容性缺口。`verify-persistence-changes` 报告历史事件 `target/admission` 的 `peers` 和 `target` 两个必填字段尚未声明。与上述 DSHU 基线逐项比对，当前目录中的持久化根、类型摘要和节点相同，只有三条类型的源代码行号移动。维护者需用含旧事件的资料副本验证读取与重放，按[持久化规则](../persistence/README.md)补齐真实兼容决定，并复跑目录及变更声明检查后再验收内核升级。

每个节点开始前记录输入提交、锁文件和运行时版本。数据迁移与安装验证使用已有资料的副本，并保留升级前可启动的安装包及对应完整资料备份。失败时保留候选日志，用旧安装包和升级前资料副本复验；已经升级过的 SQLite 不能交给旧版直接写入。对已推送节点采用后续修复或回退提交。[已发布数据格式状态](../persistence/status.md)

下一位维护者从节点 1 和候选模式清单开始，逐项附上提交、执行命令、产物摘要及待验平台。候选仍有缺口时，在[交付清单](../TODO.md)记录实际内核版本和首个未通过节点。
