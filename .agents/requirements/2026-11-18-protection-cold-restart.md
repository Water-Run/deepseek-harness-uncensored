# Windows 本地文件与 SQLite 保护冷重启验收

状态：已使用系统安装的 Windows 18.2、DSH rc.4 完成独立 Host 的真实执行验收。没有修改用户运行配置或模型账号，没有发布 Release。本项覆盖 `09.04`、`09.05`、`09.07` 和 `09.11` 的 Windows 本地文件及 SQLite 执行，远端服务器、远端数据库物理身份及其他协议继续单独验收。

## 执行与持久化

使用公开的可选保护组合，在独立 home 和 workspace 中挂载实际保护、文件、HTTP 与代理提供方。初始规则为空，境内保护关闭，三类自有目录均可读写。通过所有者 Remote 设置接口保存完全保护、只读审计和测试目录规则，没有直接修改规则数据库。

| 检查 | 重启前 | 新 Host 重启后 |
| --- | --- | --- |
| 完全保护目录读取与写入 | `TARGET_FULLY_PROTECTED` | 同样拒绝 |
| 只读审计目录读取 | 返回原内容 | 返回原内容 |
| 只读审计目录写入 | `TARGET_READ_ONLY` | 同样拒绝 |
| 测试目录写入不同标记 | 新内容独立回读一致 | 第二份新内容独立回读一致 |
| 规则修订与偏好 | 已提交修订 2 | 重新打开后完全一致 |
| 已有审计记录 | 27 条 | 重启后仍可读取 27 条 |

首次规则保存前已取得文件目标句柄；保存规则后，直接复用旧句柄的读写仍被实际文件提供方拒绝。完全保护与只读目录的文件内容由 Host 外的独立读取核对，没有被拒绝的操作改写。

随后通过设置接口清空规则，再用实际提供方将三类文件写入新的关闭阶段标记；独立回读一致。该过程验证关闭后的真实文件效果，不只检查调用返回值。两次 Host 均完成停止，应用 ASAR 在检查前后不变，模型请求为零。

## SQLite 本地数据库

系统安装的 18.2 Host 挂载三个独立 SQLite 文件绑定。经认证的所有者接口提交完全保护、只读审计和测试规则。实际 SQLite 执行器使用随包提供的原生 helper，测试从另一个进程以只读连接核对文件内容。

| 检查 | 重启前 | 新 Host 重启后 |
| --- | --- | --- |
| 完全保护库读取 | `TARGET_FULLY_PROTECTED` | 同样拒绝，原始内容保留 |
| 只读审计库读取 | 返回原内容 | 返回原内容 |
| 只读审计库写入 | `SQLITE_READ_ONLY` | 同样拒绝，原始内容保留 |
| 测试库写入 | 第一次写入经独立回读确认 | 第二次写入经独立回读确认 |
| 规则和审计 | 修订 2，41 条审计 | 重新打开后全部保留 |

两次 Host 均确认正常退出，实装 ASAR 摘要一致。脚本、日志和回执为同日交付目录中的 `verify-installed-sqlite-protection.mjs`、`sqlite-cold-restart.log`、`sqlite-cold-restart-result.json`。
