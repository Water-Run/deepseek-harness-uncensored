# Windows 未初始化 Frida 暂停会话关闭

该修正已随 [17.5](2026-11-17.5-delivery.md) 公开预发布并保留数据安装；两平台真实包各两项用例通过，包含连续三个无脚本暂停目标的自然退出和清理。此前源码对照保留为前置证据，旧包不回写。

旧绑定的附加、脚本卸载和重置通过，失败集中于本地暂停启动、从未加载脚本就关闭的路径。17.25.1/17.26.4 候选虽然通过暂停目标用例，却产生附加用例目录占用，未纳入锁文件。[候选记录](2026-11-17-frida-version-qualification.md)

现有 REA 6.9.0 补丁仅对 Windows 本地、尚未恢复、尚未分离、尚未进入清理且无脚本的 spawn 会话调用现有私有脚本加载方法，加载 `void 0;` 完成运行时初始化。脚本进入原有注册、错误与清理流程；随后卸载脚本、恢复目标、分离会话。加载失败保留既有错误，不隐藏清理失败。其他平台、已运行目标及远端设备不进入这一步，没有增加终止用户目标的行为。

这是通过对照定位到的关闭路径修正，不声称已经证明 Frida 原生死锁的全部内部原因。Frida 仍为 17.23.2，REA 版本与上游提交保持不变。

Windows 两项真实用例通过，Linux 两项通过，包含各自同一会话内一个插桩目标和三个无脚本暂停目标。原返回值、恢复标记、自然退出及目录清理断言均保留，无用例重试。16 项桌面补丁暂存检查通过，两个平台使用包内 Node 与原生依赖，候选管理器通过临时加载钩子替换；安装目录未写入。下一版必须再次核对实际分发的补丁摘要和运行结果。
