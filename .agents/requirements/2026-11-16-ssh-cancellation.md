# SSH 转发分配的取消清理

状态：源码修复及 Linux 定向验收通过，已随 `2026.11.17.1` 检查版交付。本项取消修复不代表完整远端资源映射完成，剩余范围保留在 [TODO](../TODO.md)。

## 行为与修复

OpenSSH 控制命令成功后，流分配会检查调用者是否取消。该检查原来位于清理范围之外：在控制进程结束时取消，分配直接抛出原因，既没有创建数据套接字，也没有取消已接受的转发预留。

取消检查已移入现有转发分配的清理范围。此时的拒绝会等待取消命令和本地路径清理；成功清理后保留调用者原始原因，包括非 Error 值。不增加连接池、重连、Agent 归属推断或新的设置；共享连接仍属部署级，不绑定首个调用者。

## 验证与范围

新增两项回归在修复前均失败，记录为只执行一次转发控制命令、缺少取消命令。修复后，启动与释放两个所属文件共 43 项通过；控制取消完成的屏障验证在清理完成之前不提前拒绝，且没有创建数据套接字。两个独立测试进程并发，每组各 43 项通过。

同一文件集合对 `packages/ssh/ssh/src/index.ts` 的语句、分支、函数和行覆盖率均为 100%；这不是整个 SSH 包或全仓覆盖率。8 项产物构建、随后 2 项聚合编译、定向 lint 和 README 双语配对通过。命令与网络接口为测试替身，管理 RPC 使用实际协议实现；没有连接真实服务器，也未修改生产目标或用户 SSH 配置。

测试的模拟进程关闭回调设置确定的取消时点，不使用固定睡眠。取消命令使用可释放屏障，夹具先释放该屏障再关闭服务，失败时也能收尾。原始取消原因、无数据套接字、已发出取消命令及本地路径清理均有断言。

材料位于 `%USERPROFILE%/DSHU-Deliveries/20261116/`，前缀 `ssh-cancel-`：`before.log` 为修复前两项失败，`fixed.log` 为 43 项通过，`concurrent-{1,2}.log` 为并发，`coverage.log` 为单文件覆盖，`build-artifacts.log`、`build-check.log` 和 `lint.log` 为构建与检查。修改未改变 Session 事件、持久化字段或模型输出文本。
