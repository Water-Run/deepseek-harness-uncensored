## Windows Release 核验顺序

1. **固定候选身份。** 保存实际源码提交、工作区状态、锁文件 SHA-256、构建工具和内核及 REA 的版本与提交。显示版本用 `YYYY.MM.DD.N`，内部版本用 `YYYY.MMDD.N`。同日重构建使用新的序号。完整构建应提供客户端元数据和产物摘要，防止局部 bundle 混入候选。
2. **对照装配清单。** 按首发功能登记安装器、CLI、内核、插件、资源、运行时和随附许可。候选每条功能记录入口、默认值、验收步骤和回执。所有条目完成同一批次验证后再进入发行确认。
3. **核验最终签名文件。** 从核定的公开证书取得指纹，从独立构建回执取得预期 SHA-256。在仓库根目录运行下列只读检查并保存结果。

```powershell
$installer = Get-Item -LiteralPath '<最终 Windows x64 安装器的绝对路径>'
$receipt = & ./apps/desktop/scripts/verify-published-windows.ps1 `
    -Installer $installer.FullName -Thumbprint '<公开发布证书指纹>' -ExpectedSha256 '<候选回执中的 SHA-256>'
$receipt | ConvertTo-Json
'{0}  {1}' -f $receipt.SHA256, $receipt.File
```

签名回执应同时核对发布者、内嵌 Authenticode 签名、时间戳和文件摘要。用输出的摘要行填 `SHA256SUMS.txt`。包含在线升级时，按[首发操作说明](windows-x64-first-release.md#核对候选安装器)复算同一安装器的 `.blockmap`，核对 `latest.yml` 的内部分发版本、唯一安装器名称、大小和 SHA-512。

4. **在独立资料副本上实装。** 验收全新安装与保留资料升级两条路径。核对同版修复、换目录失败后的恢复、会话及附件回读，再重跑候选受影响的功能。发生失败时保留故障回执和资料副本。
5. **交由用户审核发行材料。** 将和候选对应的标签、标题、平台说明、功能及默认值、已知问题、安装器、摘要和回退说明交给用户。在线更新资产与同一签名安装器匹配。用户确认后手动发布与回读，正式签名和公开发布各自留档。

每批待填的字段包括候选显示版本、内部分发版本、源码提交、依赖锁摘要、DSH 与 REA 来源、安装器名及 SHA-256、签名回执、备份、回退包、同批次测试报告、许可缺口和发行确认。

## 接手顺序

1. 对照当前 `main` 和本机实装提交，确定首发实际采用的 DSH 内核。沿用 rc.4 时从[已核对的 rc.4 源码](windows-x64-first-release.md#沿用-rc4-的源码基线)核对实装之后的修复。53 个源码文件已通过补丁应用检查。隔离 rc.4 组合通过 35 项启动与客户端版本测试及 61 项更新测试。迁移更新器时需把 `builder-util-runtime@9.7.0` 补为桌面直接依赖，并复用 rc.4 锁文件已有的快照。完整候选继续按首发清单装配和验证，版本以构建回执为准。
2. 核对候选应装配的功能和依赖。接续三组可选保护时先补目标判定及资源执行保护，再验收审计、模式设置和代理联动。六项第三方声明分别保留证据和结论。
3. 用[候选回执模板](windows-x64-first-release.md#候选回执模板)登记同一包的签名、实装和回退结果。历史验证记录可供复现，正式候选的验收结果需绑定其自己的 SHA-256。

桌面启动与更新的 32 文件迁移补丁已通过 rc.4 临时索引应用、逐文件回读及锁文件核对。补丁、摘要及适用范围见[沿用 rc.4 的源码基线](windows-x64-first-release.md#沿用-rc4-的源码基线)。

本机的可转交交接材料放在 `%USERPROFILE%/DSHU-Deliveries/20261119/first-release-handoff/`。按归档旁的 SHA-256 核对文件，从压缩包中的 `README.md` 进入。压缩包记录对应的源码提交，并收录首发交接、候选核验和定向证据。正式安装器和用户资料继续从上面的本机恢复入口查找。
