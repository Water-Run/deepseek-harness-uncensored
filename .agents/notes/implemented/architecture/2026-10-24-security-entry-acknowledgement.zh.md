# Agent Note：新网安对话的首次进入确认

状态：已实现

[English](2026-10-24-security-entry-acknowledgement.md) | 中文

## 问题

网安模式此前没有进入门禁。用户可以为新对话选择网安，并立即以最强工具组合执行命令；责任说明只存在于模式指南中，保护后端又尚未接入。需求要求每次 Host 启动只对第一个进入网安的新主对话展示一次确认；已有对话继续使用独立的临时切换权限。

确认必须读取真实保护状态，不能只看配置开关。延后的目标保护工作目前没有运行状态，因此产品必须如实报告保护不可用，不能声称保护已开启。确认也不能变成目标授权或执行门禁。

## 决定

把策略放在 `@deepseek-ai/dsh-agent-preset-registry` 中，作为与现有模式切换权限并列的第二套独立权限：

- `SecurityEntryPermission` 持有 Host 生命周期内的确认、一个待处理挑战、单调阅读计时、挑战有效期和 Host 签发的声明。它与模式切换权限不共享状态。
- 注册表的 `select` 对尚未确认的空白新对话进入配置的网安 preset 返回 `security-entry/required`。已有对话跳过该检查，继续使用临时切换策略。
- `session.create` 通过 `assertNewConversationPreset` 拒绝显式指定的网安 preset；未指定 preset 的请求保持部署默认值。未组合注册表的 headless 与 SDK 组合不受影响。
- Web profile 开启 `requireSecurityEntryAcknowledgement` 并指定 `securityEntryPreset`；其他 profile 保持默认关闭。
- 部署可提供 `securityProtection` 服务，其 `read(): SecurityProtectionStatus` 返回运行状态与修订号，并在变化后发出 `security-protection/changed`。注册表据此使已打开的挑战失效并发布新状态。没有提供方时状态为 `unavailable`。
- 对话框逐字展示挑战中的声明，等待倒计时结束，并由 Host 校验同一份声明。客户端不保存第二份文本。
- 客户端控制器在选择进入座位前拦截，因此在 Host 接受前，模式强调色、模式标签和对话模式都不会改变。取消后清空暂存选择，草稿和原模式保持不变。

## 考虑过的替代方案

- **与模式切换权限合并。** 不采用：两项确认的范围不同（新对话与已有对话）、状态生命周期不同、界面也不同。共用一个开关会让一项满足另一项。
- **把配置里的 `enabled` 字段当作保护状态。** 不采用：它无法区分真正运行的提供方与已归档或损坏的后端。提供方契约报告可用性和修订号。
- **把确认写入设置。** 不采用：需求和权限边界都要求只保存在 Host 运行内存中。页面刷新因 Host 仍在而保留；Host 重启后重新询问。
- **只校验客户端布尔值或非空声明。** 不采用：Host 签发一次性挑战，绑定会话和保护修订号，并要求逐字文本。
- **只在界面拦截。** 不采用：`select` 与显式创建才是授予 preset 的后端操作，拒绝必须放在那里。

## 后果

- 每次 Host 启动后的第一个新网安对话展示一次对话框；同一次启动内后续新对话直接进入，已有对话永远看不到它。
- 没有保护提供方时，对话框说明无法确认保护并要求输入声明。这是延后的执行保护恢复前 Web 产品的真实状态。
- 确认只记录操作者的声明；它不执行目标规则，也不能证明对第三方目标的授权。
- 提供方在倒计时期间改变状态会使挑战失效；客户端重新读取并开始新的阅读计时。
