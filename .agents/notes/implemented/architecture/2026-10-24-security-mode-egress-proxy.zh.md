# Agent Note：把网安模式出口代理做成会话作用域接缝

Status: implemented

[English](2026-10-24-security-mode-egress-proxy.md) | 中文

## 问题

网安预设需要一个独立的代理来处理目标流量：配置、真实连接检查和请求/响应查看。直接"设置 `HTTP_PROXY`"有三处错误。

- 进程已经根据启动环境解析出一套出站代理策略，并把它安装为 undici 的全局 dispatcher，也就是 `fetch` 实际使用的路由。再往那里装第二套代理，会把模型 API、登录、余额和更新检查一起带走。
- 覆盖范围必须跟随对话的模式。工具参数或客户端传来的模式字符串不能决定它，只有会话的持久记录可以。
- 经过代理的 HTTPS 在不拦截 TLS 时是不可见的。需求禁止放宽校验，因此可捕获的正文只能来自真正写出请求的那一层。

## 决定

把能力接缝与其提供者分开，并让两边都显式。

- `@deepseek-ai/dsh-security-proxy` 是服务定义（`ctx.securityProxy`）：`route(subject, tool)`、`environment(subject, tool)`、`fetchTarget(subject, url, signal)`。`subject` 在结构上只需要携带会话身份，因此 `Agent` 天然满足，测试也可以直接构造。
- `@deepseek-ai/dsh-security-proxy-local` 是提供者。它拥有一个设置文档、一个有界捕获存储、一个上游 `ProxyAgent`、每个对话一个回环链式代理，以及状态机。它从不调用 `installProxyFromEnvironment`，也从不触碰全局 dispatcher。
- 覆盖判定读取最后一条已提交的 `agent-preset/selected` 事件或会话头，并通过插件从 `session/event` 维护的缓存更新。该事件属于预设包，但预设包没有发布 session 子路径，因此接缝重新声明它；载荷一旦变化会编译报错，而不是静默错配。
- 受控的 `web_fetch` 在客户端层记录：它构造请求、读取响应，并在脱敏后保存两者。子进程只在那一次 spawn 的环境里获得每对话的回环监听；经它的明文 HTTP 完整捕获，CONNECT 只记录元信息并标注 `tunnel-metadata-only`。
- 脱敏只在写入时做一次：含密钥的请求头与常见 JSON/表单密钥字段在任何人读取该行之前就被替换。条数、正文字节、保留时长各有上限；正文只在内存，重启不会复活旧流量。
- 未开启代理的提醒是一个转发的 Host 事件（`security-proxy/warning`），在引擎内按对话去重、销毁时清除，从不改变代理状态。

## 备选方案

| 方案 | 否决原因 |
| --- | --- |
| 按模式安装第二个全局 dispatcher | 它天然是进程级的，模型与控制面流量会跟着走。 |
| 让子进程直接连上游 | 既没有归属也没有捕获；只有每对话独立监听才能让"会话"这一列诚实。 |
| 拦截 TLS 以显示 HTTPS 正文 | 需求禁止，而且会把所有目标的凭据放进应用的信任路径。 |
| 由工具传 `mode` 参数 | 模型可见参数不能成为网络策略的权威。 |

## 影响

- 只有网安预设受影响；其他模式继续使用启动环境策略与默认提供者。
- 网安会话中的 `web_fetch` 返回同样的 `WebFetchResult` 结构；失败以带类型的 `WebError` 代码出现，因此会话记录能解释代理故障，而无需新增工具。
- 浏览器工具、MCP、常驻终端、委派子代理以及忽略代理环境变量的程序仍不在覆盖范围；设置界面陈述真实覆盖，而不是暗示已覆盖。
- 回环监听没有本地身份验证。它绑定 `127.0.0.1`，只在其对话存在期间运行，并在设置变更与 Host 退出时关闭。
- 本构建没有挂载真正执行的目标保护，因此 `10.05` 仍未完成：代理既不调用保护钩子，也不声称它已生效。
