# DSHU 使用手册

[English](dshu.md) | 中文

## 概述

DSHU 是 WaterRun 维护的 DeepSeek Harness 独立分支，提供内置破甲提示词、四种模式和单独的桌面应用。本手册面向已安装桌面版或已启动 Web 服务的用户，从配置模型开始，说明怎样组织任务、使用辅助对话、查看花费和管理长期资料。DSHU 与官方版分别保存配置和会话；模型能力、接口可用性与费用取决于所用提供方。当前交付版本和验收范围以[开发清单](../../../.agents/TODO.md)为准，未发布的源码改动不等于安装版已有功能。

<a id="first-task"></a>
## 完成第一个任务

从一个范围明确、可以检查结果的任务开始。准备好模型凭据和所需资料后，先验证连接，再扩大任务范围。

1. 打开**设置 → 模型**，配置提供方、接口与凭据，保存后选择模型。第三方接口还需正确的协议和模型 ID；详细步骤见[模型配置](providers.zh.md)。
2. 创建新会话，选择工作区。处理项目文件时选择对应目录；一般问答可选择**不在工作区工作**，不必为了发消息创建目录。
3. 在第一次发送前选择模式。缺省适合日常任务；网安、逆向和写作提供各自的资料与工作流程。已有会话默认保留原模式。
4. 写明输入、预期结果与验证方式，然后发送。需要的文件或图片应一并提供；不要假定模型已经读过未发送的资料。
5. 查看实际修改、执行结果与未完成事项。工具报错、缺少依赖或没有执行的检查，应作为后续任务保留。

例如，在一个已有项目的工作区发送：

> 找到这个项目的入口和启动方式，解释当前构建失败的原因。修复后运行受影响的检查，最后列出修改、验证结果和仍然存在的问题。

成功的结果应能定位到具体文件或观察值，并说明检查是否实际运行。只返回一段建议，不等于已经修改或验证。

<a id="modes"></a>
## 选择合适的模式

模式决定专用资料、工作流程与可用工具组合。四种模式共用内置破甲提示词；模型仍可能出错，任务结果应以文件、运行观察与复核为准。设置中的**模式说明**与**如何使用**仅打开指南，不会切换会话；已有会话只有在空闲且临时允许切换时才可变更模式。

### 缺省：开发与日常任务

![缺省模式，蓝色](../../assets/dshu/mode-default.svg)

缺省可读取和修改文件、运行命令、检索资料，并按任务使用协作与工作流。适合修复程序、理解仓库、整理资料和完成可执行交付。先提供项目路径、错误现象和完成标准，再让智能体调查、修改并验证。

> 复现这个接口返回错误的问题，找出原因，修改后验证正常与异常输入；不要把仅凭代码推断的结果写成实际执行结果。

**检查交付：** 修改文件、触发条件、验证命令与结果齐全；无法运行的检查有明确原因。

### 网安：调查、证据与验证

![网安模式，红色](../../assets/dshu/mode-security.svg)

网安提供七类现场手册、案件记录、报告与独立代理。首次进入新的网安会话有责任确认；案件保存在 `.security/`，可记录目标、证据、发现和待办，供后续对话继续。提供方、模型与实际执行环境共同决定可完成的任务，手册不会自动安装外部工具。

> 检查这个测试应用的认证与上传流程，在本地复现可疑问题，指出影响位置，完成修复和回归，并把证据与未决问题写入案件记录。

**检查交付：** 发现对应到目标、位置与复现条件，区分观察、推测和未能执行的验证。需要代理时在模式配置中单独启用；顶部未开启提醒可以开关。目标、服务器与数据库保护默认关闭，选择网安不会自动开启。[执行保护的覆盖与限制](../../../packages/guard/target-protection/README.zh.md)应在启用前核对。

### 逆向：样本、调用路径与协议

![逆向模式，绿色](../../assets/dshu/mode-reverse.svg)

逆向提供八类分析手册、`.reverse/` 案件记录和内置 REA。可围绕程序行为、文件格式、协议与动态观察开展分析。先保留原始样本，提供平台、架构线索和代表性输入，再选择适合的工具；修改后的样本与产物应单独保存。

> 记录这个样本的哈希和架构，定位解析器入口，追踪关键调用，用独立输入验证判断，并保存脚本和未决假设。

**检查交付：** 样本身份、地址或偏移、调用或运行证据、可复用脚本与不确定性清楚。REA 已内置；Ghidra、Java、IDA、Hopper 等可选引擎仍需各自配置。连接检测成功不等于所有引擎、许可证或目标进程都已就绪。

### 写作：设定、文风与长篇延续

![写作模式，金色](../../assets/dshu/mode-writing.svg)

写作适合小说、剧本与长文，提供参考文风、六轴风格卡和 `story/bible/` 设定集。只有选中的资料会进入模型请求；模式配置可管理参考与设定，后续对话可沿保留的资料继续。写作组合不挂载终端或代码执行工具。

> 按选定的人物设定和参考文风续写下一场。保持当前视角、时间线与信息范围，检查与设定冲突的地方，并给出完整正文。

**检查交付：** 正文符合指定长度、视角与人物关系；设定冲突和仍待确认的信息单独说明。长期作品先整理人物、时间线和世界规则，再逐场推进。

<a id="conversations"></a>
## 主线、旁问与随问

主线执行任务，旁问用于连续讨论，随问用于临时确认。三者各有用途；旁问与随问不会把主线历史复制成侧栏里的普通会话。

| 入口 | 适合什么 | 历史与行为 |
| --- | --- | --- |
| 主输入框 | 推进当前任务、发送新要求 | 保留主线历史；执行中的发送方式取决于忙碌时发送设置。 |
| `/side 问题` | 需要连续追问、解释或传图 | 打开旁问并发送该问题；只输入 `/side` 可打开或重开。 |
| `/btw 问题` | 一次简短确认 | 在主对话内显示简短回复，不新建普通会话。 |
| 旁问中的 `/clear` | 重新开始旁问 | 清理旁问自己的历史；主线历史保留，旁问仍能参考主线。 |

旁问在每次提问时参考主线已经完成的新进展，并保存自己的独立历史。主线也可以主动查看相应旁问，了解讨论内容；不要把旁问的说明当作已经向主线发送了新的执行要求。

关闭旁问默认保留历史，重新打开可以继续。需要关闭后自动清理时，在设置中开启**旁问关闭后自动清除上下文**；默认关闭。`/clear` 只在旁问内可用，不能用它清理主对话。

旁问支持图像附件。附图时说明希望检查的位置或现象，并使用支持图像的模型；附件已添加不代表提供方一定支持该类型。

<a id="spending"></a>
## 余额、对话费用与额度限制

这三项回答不同的问题：余额是账户最近采样值，对话费用是本地估算的任务消耗，限额是你选择启用的本地支出控制。它们不能互相替代，也不是提供方的正式账单。

### 查看余额与曲线

侧栏余额卡片保持紧凑，点击可查看统计或刷新。默认每 15 秒采样，可设置为最短 3 秒。公开 API 不提供完整历史，曲线从本机采样累积；悬浮、轻触或聚焦后使用方向键，可查看具体时点与金额。

充值等余额增加以竖向虚线表示；长时间无变化的区间用横向虚线缩短，避免平稳时段挤掉先前变化。余额差可能包含充值、赠金与到期扣减，不应直接解释为本次对话费用。

### 设置独立限额

设置 → 额度提供 15 分钟、1 小时、5 小时、1 天、7 天和 30 天窗口。新安装默认全部关闭，优先展示 5 小时与 7 天，其余可展开。每项可单独启用、修改金额和重置；底部有全部关闭和全部重置。

执行前按请求预留费用，返回用量后再结算，因此在途请求可能暂时占用额度。重置的是本地限额统计，不会充值，也不会撤销提供方已经收取的费用；费用估算、预留与失败处理由[额度控制说明](../../../packages/guard/spend-limit/README.md)定义。

### 达到限额之后

额度不足时，暂停横幅应显示原因、可用的预计恢复时间与快捷重置。可等待滚动窗口恢复，或在确认后调整、关闭或重置相应限制。只有开启自动恢复时，额度恢复后才自动继续被暂停的任务；等待其他请求结算释放预留也可能恢复可用额度。

底栏的金额可展开当前对话的费用曲线，限额项可展开已启用窗口的进度。提供方余额耗尽、认证失败与网络故障是另外的错误，应按具体错误处理，不能靠重置本地统计修复。

<a id="memory"></a>
## 记忆、资料与输入预测

跨对话记忆保存可检索的长期信息，模式资料保存当前工作所需的参考，两者都需要明确范围。它们不会自动把其他会话的完整历史附加到每次请求。

- **长期事实与偏好：** 使用结构化记忆，按可用范围检索、审阅和编辑。自动提炼默认关闭；启用后产生的模型调用按提供方规则计费。
- **项目或案件的详细证据：** 保存到工作区、`.security/` 或 `.reverse/` 案件文件。选定网安案件备注可经审阅存入记忆，默认限定当前工作区与网安模式；完整证据仍以案件文件为准。
- **写作资料：** 在模式配置中选择参考文风与设定，不需要的资料取消选择。未选中的资料不会仅因保存在列表中就进入模型请求。
- **输入预测：** 默认开启，在主线、旁问与随问按各自草稿预测。灰字是建议，按 Tab 填入后仍由你决定是否发送；预测会调用当前模型并可能产生费用。

当回复沿用错误背景时，先检查已选资料、记忆范围和旁问历史，再决定编辑记忆、取消资料选择或使用旁问 `/clear`。删除会话与编辑长期记忆是不同操作。

<a id="tools"></a>
## 工具、插件与 REA

桌面版集成 REA，无需另外安装 REA 本身。设置 → 模式 → 逆向配置可以检测连接，并按需指定可选引擎；版本、仓库与固定来源提交见关于页及[REA 说明](../../../packages/mcp/rea/README.zh.md)。修改配置会重建连接，原先打开的样本需要重新打开。

插件用于扩展模型提供方、工具和界面，MCP 用于连接外部工具服务。配置成功后先运行一个范围明确的小任务，核对执行后端、输出及失败提示。插件可见、工具目录可见与真正完成任务是三个不同的检查；外部程序、凭据和许可证仍需满足各自要求。

网安独立代理只在适用执行路径中生效。连接元数据不等于已检查加密正文；终端程序也必须遵守代理配置。可选保护的设置页会显示各执行器覆盖，尚未覆盖的协议、远端环境与入站场景不能仅凭开关推断为受保护。

<a id="defaults"></a>
## 外观与默认设置

模式色用于识别当前任务：缺省蓝、网安红、逆向绿、写作金。外观支持跟随系统、浅色、深色和日出日落；指南使用对应模式配色，阅读指南不会改动当前会话。

| 设置 | 新安装默认值 | 说明 |
| --- | --- | --- |
| 新会话模式 | 缺省 | 第一次发送前可选择其他模式。 |
| 已有会话切换模式 | 不允许 | 在设置中临时允许，且会话空闲后才可切换。 |
| 六项支出限额 | 全部关闭 | 5 小时与 7 天只是优先展示，并非自动启用。 |
| 额度自动恢复 | 关闭 | 开启后，额度恢复时继续被暂停的任务。 |
| 目标、服务器与数据库保护 | 关闭 | 属于可选进阶配置，按执行器核对覆盖。 |
| 余额采样间隔 | 15 秒 | 最短可设置 3 秒。 |
| 输入预测 | 开启 | 使用当前模型，可能产生费用。 |
| 旁问关闭后清理 | 关闭 | 可手动在旁问中发送 `/clear`。 |
| 自动记忆提炼 | 关闭 | 开启前选择所需范围并审阅保存结果。 |

这些是新安装的初始设置；更新时会保留已有配置，不能根据默认值推断当前开关状态。

<a id="data"></a>
## 数据、更新与恢复

DSHU 使用独立程序标识和数据目录，默认数据根目录为 `~/.dsh-uncensored`，可通过 `DSH_UNCENSORED_HOME` 改写。官方版和 DSHU 可并存，配置与会话不自动共享。工作区文件、外部工具的数据和提供方账单不属于应用数据备份的全部范围。

版本使用 `YYYY.MM.DD.N`，最后一项为当天构建序号。关于页分别展示 DSHU 版本、基于的 DSH 版本、作者 WaterRun、编译信息和依赖来源；日期版本并不取代 DSH 或 REA 自己的版本号。

更新前关闭 DSHU，并保留数据目录及重要工作区文件的备份。使用明确标记为 DSHU、与平台匹配的安装包；卸载时留意数据清理选项。正式签名、在线升级、系统重启及自动回退的完整发行验收尚未完成，当前检查包的验证与恢复入口见[交付记录](../../../.agents/HANDOFF.md)。不要用旧程序直接写入未经验证的新版本数据。

<a id="troubleshooting"></a>
## 故障排查

先记录实际错误、发生时间、模式与复现步骤，再缩小到模型、工具、额度或界面。反馈时可附截图和版本信息，凭据应脱敏。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 模型无法响应 | 提供方、模型 ID、接口协议、凭据与原始错误 | 按[模型配置](providers.zh.md)检查；本地重置额度不能修复认证或服务端限额。 |
| 任务暂停不动 | 额度横幅、已启用窗口、在途预留 | 等待结算或恢复；按需重置对应窗口，检查自动恢复开关。 |
| `/side 问题` 没有出现预期内容 | 是否在主输入框发送、是否打开了对应旁问 | 只输入 `/side` 重开核对；需要新历史时在旁问发送 `/clear`。 |
| 旁问无法理解图片 | 附件是否添加成功、当前模型是否支持图像 | 换用支持图像的模型，补充位置与检查目的。 |
| 阅读模式指南后模式没变 | 当前会话的模式与锁定状态 | 阅读帮助不会切换；新会话发送前选择，旧会话需临时允许切换。 |
| REA 已连接但分析失败 | 对应引擎、路径、运行环境、权限与许可证 | 用小样本检查实际执行，保留完整错误；目录发现不算引擎验收。 |
| 删除会话报错 | 对应会话、子任务、执行状态与错误提示 | 保留截图及版本并[反馈问题](https://github.com/Water-Run/deepseek-harness-uncensored/issues/new/choose)，不要通过手删数据库修复。 |
| 余额历史不完整 | 是否首次开始采样、是否存在无变化压缩区间 | 从当前采样继续积累；公开接口不能补回未采样的完整余额历史。 |
