# 工作区文件变更订阅

[English](guide.md) | 中文

## 变更

`workspaceFiles.changes` 过去会逐条排队观察事件，包括目标解析前的事件。现在只为已解析的目标保留一个待刷新标记。密集变更可以合并为一帧 `change`，其中包含当前元数据。原生监听器就绪后仍会发送 `ready`。

内置文件预览读取元数据时只保留有限的待处理通知。重连后刷新当前状态。若绑定到新的规范路径，而该路径的通知可能已被淘汰，预览会再次读取元数据。

## 迁移

1. `workspaceFiles.changes` 产出 `ready` 后，调用 `workspaceFiles.stat` 获取初始状态。这样可覆盖目标解析前发生的变更。内置文件预览已按此方式读取元数据。
2. 将每帧 `change` 视为刷新当前元数据的通知。若消费方曾按帧数统计写入次数，改用写入方自己的操作日志统计。
3. 在拉取下一帧前多次写入被监听的文件，确认消费方刷新到了最后的文件状态。
